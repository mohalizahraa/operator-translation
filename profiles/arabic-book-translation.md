# Arabic Book Translation Profile — Task Router

Use with Core + THINK + ACT + KNOWLEDGE + ASSURANCE for Arabic→English books, manuscripts, long-form scholarly/religious works, or other publication-oriented document translation where fidelity, complete text-surface coverage, formatting preservation, and a clean English or explicitly bilingual edition matter. Add other Operator owners/profiles whenever their concern is materially relevant.

This profile is additive, not a separate operating system: apply the rest of Operator by dependency, while keeping project truth cleanly separated. Do not import unrelated project-specific context, decisions, or machinery (for example Nexus) into translation work merely because both use Operator; load only the active translation project's own authorities when relevant.

This profile specializes translation procedure. It does not weaken source authority, execution, documentation, or verification rules owned by the parent protocol.


## Universal house standard, speed and routing

**One shared mandatory Arabic→English translation and formatting standard governs every book handled in the Haydari Translation Workbench, regardless of whether Zahraa or Mohammed owns or requests it.** Collaborator/book identity affects discovery and attribution only; it never selects lower or alternate quality requirements. The live formatting house profile is REAL SCALE v3, inheriting v2 and v1 except explicit later overrides.

**Quality is a hard acceptance constraint; optimize speed subject to it.** Target exceptional publication-grade faithfulness to the authoritative Arabic, exact scholarly terminology and nuance, elegant natural English, all source-bearing surfaces, line-by-line revision, genuine native document semantics, and full verification. Save time through deterministic source/target lookup, verified glossary reuse, efficient batches, mechanical QA and avoiding redundant work. Do not trade away a fidelity or production gate for throughput.

The router is small by design; the following children preserve **all** rules from the former monolithic profile, including numbered sections and cross-references:

| Active task | Required owner(s) |
| --- | --- |

**A formatting pass must route all applicable rules in the first pass, with identical mandatory weight.** The split is progressive disclosure for work not involved; it is not permission to leave subtler formatting rules out. The section numbers in the child documents remain the original cross-reference identifiers. Canonical Operator parents still govern reasoning, execution, documentation and verification; the Arabic source governs text meaning; the Workbench owns operational project state.

## 0. Interpret translation and formatting shorthand as full-profile work

For any Arabic→English book or manuscript governed by this routed profile family, user wording such as `translate this book`, `format it`, `do a formatting pass`, `finish formatting`, or `do another formatting pass` automatically inherits this routed profile family. The user does not need to restate its individual rules.

A **formatting pass** is not a cosmetic spot-fix. It means apply and verify the **entire currently applicable translation-profile formatting and production contract across the whole edition**, including the active edition-formatting profile/overlay and every applicable requirement for semantic document roles, notes, the native TOC, major openings, page boundaries, typography, indentation/spacing, sacred-glyph rendering, image/text presentation surfaces, pagination properties, and final rendered checks. Reuse already-valid evidence and already-correct work rather than redoing it for activity's sake; a formatting pass does not by itself require retranslation or reopening source-fidelity review that is still valid. But any known unmet requirement in this routed profile family that affects the edition's claimed formatting or publication state must be repaired or remain an explicit blocker.

**First-pass completeness; equal mandatory standing (founder requirement).** On the **first** requested formatting pass, apply and verify **every applicable formatting and production rule** from **every section of this routed profile family** and every activated edition overlay across the entire book. No rule is optional, lower-priority for acceptance, or deferrable to a supposed second/cleanup pass merely because it is subtle, labor-intensive, technical, near the end of the document, or less visually noticeable. Inspect the whole profile before work, enumerate the applicable requirements and their whole-edition surfaces, and retain a per-requirement PASS / BLOCKED / NOT APPLICABLE disposition with evidence or a concrete reason. All applicable requirements have **equal acceptance weight**, though their **execution order may follow dependencies** (for example, migrating native footnotes before final TOC refresh); iterative repair and re-rendering can be part of one first pass. A first pass with even one known unmet applicable requirement is **OPEN, not complete**. Do not silently classify a difficult rule as not applicable, count spot checks as full-edition evidence, or claim later passes will supply any omitted rule. Preserve genuinely valid preexisting work and evidence; this rule does not require needless retranslation or repeating previously verified checks that remain valid.

When translation and formatting are requested together, completion is conjunctive:

> **translation/text gates pass + the full applicable formatting/production profile is applied + invalidated downstream evidence is rerun + the terminal native-TOC fixed-point/render verification passes.**

Do not call a formatting pass `done`, `complete`, or equivalent after only fixing the examples the user named, after a sampled/structural check, or while a known applicable profile requirement remains unmet. Whole-book denominators and outlier-driven class scans still apply. If an applicable profile requirement cannot be satisfied with the available tooling or authority, state the exact blocker and do not report the formatting pass complete.
