# Workbench book-processing workflow

Status: user-approved execution plan, captured 2026-10-09. This project-owned file survives translation-projection synchronization. The current [Operator router](../AGENTS.md), [Arabic-book profile](../profiles/arabic-book-translation.md), and [Workbench contract](README.md) govern fidelity, formatting, access, progress, and publication. This plan adds scheduling and handoff guidance, not a weaker quality standard.

## Pipeline, not whole-book stage barriers

Prepare the active book once, then overlap source preparation/OCR for upcoming batches with translation of a source-checked batch. Do not require all OCR to finish before translation can begin. Whole-book extraction/OCR is allowed when measured startup costs make it cheaper and it does not delay the first usable batch or required review. Keep the ready queue bounded by downstream capacity; more busy machines are not automatically faster.

Actual translation content stays on one book at a time unless the user explicitly authorizes interleaving. Deterministic mechanical preparation may span books, as the current execution-substrate profile permits. Never trade source fidelity, complete text-surface coverage, or checkpoint verification for throughput.

## Founder directive: fastest possible execution with every quality rule intact (2026-11-16)

**Optimize for the shortest real elapsed time to fully verified, release-quality completion—not maximum raw pages drafted or apparent activity.** This is a standing instruction for all 174 included books and their source reconciliation, translation, first-pass formatting, final integration, independent assurance, private tracking and eventual final website sync. Apply the entire current Operator Protocol, all task-relevant profiles, project rules and every still-applicable founder instruction; **no speed optimization may lower or skip a required quality, provenance, permissions, privacy, accuracy, human-review or verification gate**. Missing evidence remains open rather than silently downgraded.

- **Reduce wasted work, not necessary checks.** Reuse faithful existing manuscripts verbatim; reconcile their exact contents, owner, provenance, notes, and edition before starting, preserving originals. Do not redo accepted source pages, duplicate already satisfied reviews, repeatedly load irrelevant protocol bundles, or perform redundant exports. Where source extraction, OCR, translation, copy fidelity, or format review is incomplete, do that actual work instead of crediting old labels.
- **Execute a bottleneck-aware pipeline.** Prepare upcoming source pages in bounded lookahead while an already source-checked batch is being translated; translate each coherent source unit with its complete notes and citations; perform applicable first-pass native formatting with the same batch; independently check fidelity and target revision, then record the status. Reserve final formatting for real book-wide dependencies (TOC, page numbers, layout/integration), not work unnecessarily deferred from the first pass. The one-writer manuscript lock and source identity gates remain mandatory. Do not parallelize content across books without fresh authorization; deterministic parallel preparation and nonconflicting checks may overlap when permitted.
- **Use the fastest *verified* available method.** Select OCR/translation/formatting routes from actual benchmark evidence (including extraction accuracy, notes, rendered output, setup, contention, correction and rework), not theoretical hardware speed. Choose batch size to minimize total accepted-unit cycle time. If a faster route fails the same acceptance gates or creates more rework, revert. Observe the founder's $0 paid compute rule, legal/tool licensing, privacy boundaries and exclusive Windows GPU lock.
- **Measure continuously and revise.** Timestamp actual active work for each book and separate preparation, translation, first formatting, final formatting, QA, rework and administrative wait. Compare *accepted source-aligned pages per total qualified active hour* and end-to-end book time rather than draft rate alone. After each qualified batch, re-read the private timing ledger, audit stage-specific remaining work, append forecast history, and adjust real estimates; if evidence is insufficient, retain `NOT CALIBRATED` instead of inventing a deadline. Unattended/background operation is never claimed when none exists.
- **Stay on the parent outcome.** Finish every authorized feasible step rather than stopping after a tracker or repository fix; preserve all blocked/unverified cases with an exact resume action and do not claim the 174-book programme complete before actual source, target, native formatting, reviewer and publication gates are met. Website writes remain deliberately **final-only** as already directed. Report verified throughput improvements, not unsupported claims of being the absolute fastest.

## Preferred division of work

| Work | Preferred host | Boundary |
| --- | --- | --- |
| Book setup, downloads, page mapping, reusable preparation | Windows | Keep Windows OCR/preparation environments, caches, and large working artifacts on D: by default; preserve exact source identity. |
| Arabic OCR and source-text checking | Mac | Use the selected Mac route after source-fidelity checks; OCR only missing or unreliable text. Preserve notes, reading order, diacritics, and punctuation. |
| Translation drafting | Windows | Translate coherent logical paragraphs/notes/cells with book context and terminology, not isolated storage runs. |
| Source-aligned review, formatting, native document/render checks | Mac | Use the capability the artifact requires; macOS-only PDFKit/Vision work stays on Mac. This is not an automatic second translation or deferred second formatting pass. |
| Manuscript writes and Workbench checkpoint publication | One designated writer | The writer owns the exact target revision, readback, and checkpoint; other machines return batch artifacts rather than concurrently editing the final manuscript. |

These are preferred operational roles, conditional on accessible tools and measured performance, not claims that a second Mac is registered or GitHub jobs are already routed. Translation speed depends on the translation engine and its execution location, not RAM or operating-system names alone. CPU-only independent work may overlap. Any Windows GPU-heavy work still follows [GPU scheduling](runner/GPU-SCHEDULING.md) and the exclusive host lock; two runners do not create two GPUs.

## Existing-manuscript migration and destination-account preflight

A request to move a collection of books to a different Google account is **not** authorization to turn already translated or partially translated books into blank targets. Use this gate for migrations and bulk target provisioning in addition to the normal source/translation QA pipeline.

1. Retrieve the **current live** `GET /api/projects` or exact `/api/projects/{id}` records, and establish immutable project ID, exact title/edition, assignment, status, source identity, current English link and page progress. The committed catalogue and historical handoffs are **candidate discovery**, not live Workbench truth. If live access is unavailable, pause production link/start mutations; do not silently proceed from an old manifest.
2. Inventory the authorized account's files **and all known original/historical Docs** before creating a replacement. Search stable project IDs and original/alternate titles; resolve duplicate IDs, wrong editions, shared files, moved docs and prior drafts. Read native content, not just filenames or Drive size, to classify each candidate `nonempty`, `empty`, or `unknown`. A `NOT_FOUND` from one Google identity means **unavailable**, not nonexistent/blank. Record whether that classification is actually verified.
3. For a verified nonempty existing manuscript of the verified exact edition (with no unresolved competing source), choose native Drive **copy existing** and preserve the source. Confirm the copy is owned by the exact destination account, has the intended source lineage, and retains actual content, native notes, styles, headers, tables, lists, links and structure. A matching element count or footnote count is only a structural screening check, **not proof of exact textual/style identity**. If the user said copy exactly as-is, do no translation, editorial corrections or formatting normalization on these copies.
4. Create an **empty new draft** only for a genuinely unstarted book after verified source/destination discovery establishes that no existing translation is being replaced. If any source is inaccessible or source progress is nonzero, leave its proposed target **quarantined/source-recovery**; never call it the manuscript or update the website from it. Bulk permission to establish destinations does not waive this content/identity gate.
5. Before **each** create/copy/link action, run `MIGRATION_APPROVED_OWNER_EMAIL='<privately approved email>' node scripts/manuscript-migration-preflight.mjs /private/migration-inventory.json` against current evidence. The private JSON is a one-project-or-multi-project inventory of `{destinationOwner,rows:[{project:{id,title_en},live:{id,title_en,status,sourcePageProgress,observedThisRun,apiWritable,linkBefore},expectedLinkBefore,inventoryComplete,sourceSearchComplete,sourceCandidates:[{fileId,contentState,contentVerified,editionVerified}],destinationCandidates:[{fileId,kind,ownerEmail,ownerVerified,...}],action,copySourceFileId}]}`. Accepted actions are `copy_existing`, `create_draft`, and `attach_target`; the checker is **read-only**, emits only project IDs/reason codes, and returns nonzero on blocked cases. It cannot fetch Drive metadata or replace independent readback; false caller evidence is not verified by the script.
6. Store the source→destination project/file map, original Google revision, owner, true copy verification, and explicit unresolved access/content exceptions in a **private** destination-account ledger. Don't commit IDs/URLs, book text or credentials into the public repository or paste them into publicly logged Actions. Don't blindly create a second target after a reconnect/error: list Drive and reconcile the previous write outcome first.
7. Only after the destination is fully verified, separately establish Workbench-required `anyone + writer` Drive permission and anonymous access; use the exact live project ID and compare-and-swap its current link. Read back the updated URL and unchanged status, source-page numerators, human-review and publication state before reporting the link changed. If a tool cannot grant public-Editor or the site API is unavailable, **leave the copy private and its website link unchanged**. Never downgrade the live site's access requirements or fabricate permission evidence to bypass the gate.
8. For a verified empty superseded placeholder, quarantine/rename and retain it until the live site has been checked for references; only then consider deletion under the appropriate authorization and recovery controls. Distinguish created/copied/preserved vs exact-fidelity-verified vs link-synchronized vs translation-complete in every portfolio report.

### Private native copy-parity screening (reusable per book)

Run the read-only `node scripts/compare-manuscript-native.mjs /private/original-google-docs-snapshot.json /private/copied-google-docs-snapshot.json` against full, current-revision **native Google Docs API document JSON** for the original and destination, obtained with authorized identities. The CLI must not receive a text export, filename inventory, or fabricated evidence. It emits only sanitized native text/paragraph/character-style/footnote/structure counts and returns nonzero on drift or incomplete evidence; source content, identities, revisions, and paths remain entirely private. It checks character-level font changes even when paragraph text, element counts, and footnote counts match (the historical #2 symbolic-glyph drift class).

**Never promote this partial screening to full exact-copy certification.** A passing native comparison does not prove rendered layout, media, comments, revision history, list definitions, public sharing, or Workbench readback. Record its bounded receipt in the private registry, independently verify the remaining gates, and preserve originals. Do not treat incomplete original-account access as a blank original.

**Regression:** `npm run check` runs `manuscript-migration-preflight.test.mjs` with positive and negative evidence cases, including an existing substantive manuscript incorrectly targeted for blank replacement, a restricted source, an inaccessible live API and duplicate destination identities. These tests validate the **planner's rules**, not live Google/Workbench integration. Staging/live API and Drive readback remain separately required.

### Bounded rendered-source witness when PDF extraction is corrupt

For **public original Arabic PDFs only**, the one-time self-hosted source visualization route `.github/workflows/workbench-source-visual.yml` accepts an owner-authored GitHub issue with the exact title `Workbench render: #<book ID> physical <first>-<last>` (at most four consecutive physical pages). The runner retrieves the canonical `/api/pdf/<ID>` source, checks the PDF signature/size, and renders the requested physical pages with macOS PDFKit. Base64 JPEG page images are emitted only into the workflow run log so the translation worker can inspect the actual typography and notes; temporary PDF files are removed. **The Actions logs are public in this public repository**: never use this mechanism with private sources or manuscripts. Do not paste the source Arabic, private Doc IDs, or credentials into the issue or logs. Keep render ranges bounded and use the existing public-original source only.

This is **visual access evidence, not OCR/semantic verification or a translation checkpoint**. Review the images and any source-text witness together, preserve note anchors, mark ambiguous source passages OPEN, and keep the target uncredited until source↔English comparison and the live Workbench readback gates succeed. No per-book workflow edit or paid hosted runner is required; issue triggers reuse the same tested runner path.

## Measure before calling it fastest

Use a representative hostile-case pilot before scaling a new OCR/editing route: ordinary paragraphs, dense footnotes, quotations, headings, difficult scans, and other structures actually present. Measure end-to-end verified batch cycle time, not OCR speed alone: preparation/startup, OCR, transfers, translation, correction/review, formatting, target readback, and Workbench sync. Record failures/rework and resource contention, not just successful runs. Character-error rates require human-verified reference text; missing Mac measurements remain unknown.

Tune batch size, OCR lookahead, and machine allocation against the observed bottleneck. Reduce OCR concurrency when it starves Mac review/formatting. Compare the same source/quality gates when changing the schedule; do not label this or a whole-book stage-by-stage alternative the absolute fastest without comparative evidence. Enforce $0 additional cost and check tool/model licenses before commercial use. Saving these instructions does not itself install runners, change workflow labels, deploy OCR, or modify live Workbench projects.
