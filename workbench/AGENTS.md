# Workbench Codex / runner instructions

The repository-root `AGENTS.md` and canonical projected Operator authorities continue to govern translation, formatting, and Workbench behavior. This scoped file adds project-owned book-processing and Windows GPU execution procedures; it does not replace the fresh per-turn Operator routing.

**ChatGPT-to-Workbench write bridge:** When this chat can update Google Docs but lacks a direct HTTP PATCH tool for the Workbench, **never use a fuzzy-title browser search for a production mutation**. After reading the exact Workbench `/api/projects/:id/translation-context`, checking the matching Google Docs file ID and `anyone/writer` permission metadata, submit a repository-owner-authored GitHub issue titled `Workbench start: #<exact project ID>`, whose body is one JSON object with `projectId`, exact `title`, `assignee`, `totalPages`, `documentUrl`, and `permissionEvidence:{fileId,type:"anyone",role:"writer"}`. The owner-only self-hosted workflow `.github/workflows/workbench-start-from-issue.yml` calls `workbench/scripts/start-translation.mjs` to commit the existing Docs link plus Translating in one exact-ID Workbench PATCH, without crediting any new pages. **Success requires** its verified live readback posted to the issue (the workflow closes it only on success); queued jobs, commits, or submitted issues are not completion. If the runner, HTTP API, or permission probe is unavailable, preserve the open issue and report that blocker. The existing `sync-verified-progress.mjs` / quality evidence route remains the separate authority for translated-page progress.

Before book preparation, source extraction, OCR, translation, review, formatting, or checkpoint work, read [TRANSLATION-WORKFLOW.md](TRANSLATION-WORKFLOW.md). For open-collaboration mutations, Questions Docs, QA evidence submissions, workflow transitions, or deployment/security claims, also read [SECURITY-AND-QUALITY-ROLLOUT.md](SECURITY-AND-QUALITY-ROLLOUT.md); never assume configured Cloudflare secret, real Google Docs identity or strict QA activation from code alone. Use its overlapping preparation/OCR pipeline and verified batch commit sequence. Read the current Workbench contract in [README.md](README.md) for API and workflow-state semantics. A saved machine allocation is not evidence that runners have been provisioned or jobs routed.

**Before doing any Windows GPU-heavy Arabic OCR or GPU model/translation task**, read `runner/GPU-SCHEDULING.md`, then run all GPU commands through `scripts/with-exclusive-gpu.ps1`. Two translation runners share one RTX 4070, so **one GPU-heavy job at a time, automatically and without reminders**. Never invoke GPU-heavy OCR or translation outside the exclusive host lock; do not remove the lock as a performance optimization. Mark GPU workflows `# GPU_HEAVY` and require their GPU stage to use the wrapper.

Workload separation: Windows translation/Workbench tasks stay in this repository; Mac-only PDFKit/Vision jobs stay on macOS. The Windows GPU OCR setup is experimental until source fidelity, layout accuracy, reproducibility and speed pass a representative benchmark. Never advance live verified page progress from draft OCR alone.
